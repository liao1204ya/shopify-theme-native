# 独立模块与公共能力

从原生相近模块选择骨架：容器、schema、资源加载、颜色方案、间距、动画、组件事件均遵循目标主题。只补新增能力，优先组合已有 snippet 和组件。

section 负责区域布局与配置，block 表达可重复条目，共享 snippet 或主题组件负责重复展示和交互。局部需求局部修改，公共需求修改唯一共享实现。保留现有参数兼容性，避免影响其他调用方。

运营内容用 settings/blocks；跨页面复用的结构化内容按数据关系选择 metafields/metaobjects。不要把结构化内容嵌进冗长 HTML 字符串，或用复制模板代替数据差异。具体数据类型和平台限制依实施时的官方资料确认。

个人配方包括 section 基本骨架、FAQ、Tab、响应式 YouTube、移动横滑、文本两行截断、链接下划线间距、New in 时效标签和元对象循环。它们是经验笔记：先检查闭合标签、schema、依赖和逻辑，再转换成当前主题的写法。

交互限定在实例根节点，ID 和选择器避免多实例冲突。按主题生命周期初始化并清理事件，避免编辑器重新加载后重复绑定；动态插入内容亦沿用主题初始化机制。移动布局和键盘操作跟随原生组件能力。

内容为空时避免破图、空链接和无意义占位。图片使用主题的响应式图片策略；媒体延迟加载和资源引用参照相近原生模块。模块样式有作用域，不用宽泛全局选择器修复局部问题。

验收围绕真实用法：新增两个实例、替换素材与文字、增删排序条目、切换主题配色/字体/动画、检查共享商品卡片的多个页面。无需为纯样式小改动搭建额外测试框架。
