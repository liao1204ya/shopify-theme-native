# 精简实现与桌面操作备用方案

2026-10-23 评估：参考 Ponytail 的复用与最小实现思路，按 Shopify 场景重新编写规则；Windows-MCP 仅列为可选桌面工具，不捆绑服务、安装器、生命周期 hooks 或登录自启动。不承诺截图宣传中的代码量、token 或速度收益。

## 开发与审查时执行

1. 先读受影响模板、调用方、共享 snippet、CSS 和事件流程，找到主题已有实现再动手。选择顺序：已有配置/数据 → 原生 section/snippet/组件 → 小范围扩展 → 确有必要的新模块。原生实现必须能满足本次功能与无障碍要求。
2. 首页、分类页、搜索和推荐区的产品卡片继续调用同一主题组件，传明确参数；不要复制卡片 HTML 或创建只换名称的包装层。产品/分类使用 Shopify 对象和选择器，不将数据散落硬编码。
3. 只抽取已经出现且语义一致的重复逻辑，不为假想未来建立通用框架、配置引擎或引入依赖。可读性优先，不能把复杂 Liquid/JS 压成难维护的一行。
4. 删除代码前检查引用、动态 section 加载、主题编辑器事件、应用集成和配置兼容；不能仅凭静态搜索零结果删文件。新增 JS 沿用主题生命周期，避免重复监听与重复请求，清理卸载资源。
5. 精简不能删除 schema 可编辑字段、上传入口、响应式、翻译、SEO/Schema 唯一输出、焦点管理、键盘操作、错误状态或权限校验。YMQ 金额单位、精度、边界输入、异步竞态与加购价格一致性必须保留，不能以短代码替代真实计价规则。
6. 对修改的计价、解析、状态分支执行针对性验证；覆盖正常、边界和失败场景。重复 UI 必须检查实际调用页面；避免为无行为变化的文案/CSS修改堆砌测试。记录真实检查结果，不推断测试通过。
7. 交付说明复用了什么、为何仍需新增实现、实际验证和缺口，并继续给预览链接及修改位置。除非要求，不把局部精简扩大到全站重构。

## Windows-MCP：仅在确有桌面需求时评估

这是 Windows 桌面操作 MCP 服务，不是 Shopify 主题组件，也不是无障碍合规认证工具。文件、API、CLI能完成的任务仍走原渠道；已有可用的浏览器/桌面工具优先复用。只有必要的原生应用交互、辅助技术操作或现有工具缺失时才考虑接入。

实际接入前检查当前官方依赖、固定版本、许可证及 Codex 的实际 MCP 配置格式；先列工具并验证只读状态，再做目标操作。不要照搬其他客户端配置，不自动开启登录自启动或网络监听。当前环境禁止或未提供原生桌面能力时，记录缺口，不能用该工具绕过限制。

UI操作基于当前状态，每次关键动作后核对结果；失败时重新读取状态，不盲重试提交。使用桌面工具仍不能扩大店铺/账户授权。自动化访问树或截图不能替代真实屏幕阅读器测试；未实测则注明。
