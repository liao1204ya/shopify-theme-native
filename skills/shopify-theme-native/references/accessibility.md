# Shopify 每页无障碍实施与验收

技术目标为 WCAG 2.2 A 与 AA，参考版本核查于 2026-10-21。目标不等于认证或法律合规结论。用户要求覆盖所有页面，以下是开发清单，不是完整 WCAG 标准的替代。

## 计划与页面清单

新站/全站改版从实际模板、页面和导航建立清单：首页、集合与筛选/排序、搜索与无结果、商品与变体/缺货/定制、购物车及抽屉、登录/账户（如有）、联系/询盘、关于、FAQ、博客/文章、政策页、404、密码页（如使用），以及配送、支付与结账完整过程。适用于其他已交付页面，不限于这份枚举。弹窗、Cookie 同意、聊天、订阅、推荐和第三方 App 也记录。

用 `assets/accessibility-review-template.csv` 记录每个 URL/模板及其关键状态；小站逐页检查，大量同模板商品可先自动覆盖所有可访问 URL，并按不同内容与状态分组人工检查，但必须注明实际样本与未验证页面，不将抽样标成逐页人工通过。共享组件验证不能代替页面独有内容检查。局部修改先测试涉及页面及共享组件调用方，维护未解决问题清单，避免无关重建。

按阻断购物/阅读、严重理解障碍、一般改善排序；每项记录修复负责人或负责系统、证据、复测与限制。不以“完成政策页”代替修复实际障碍。

## 视觉、阅读与语义

- 使用原生 HTML：页面语言、准确标题、main/nav/header/footer 等 landmark、合理标题层级和可用的跳到正文链接。阅读顺序与视觉顺序一致；按钮执行动作、链接导航，优先原生控件，不滥加 ARIA。
- 每个控件有可理解的可访问名称；可见标签应包含在可访问名称内。商品卡片避免重复无意义朗读；价格说明原价/现价，库存和折扣不只靠颜色或删除线。
- 信息图片提供符合上下文的 alt，装饰图片用空 alt；图表或复杂尺寸图提供相邻文字说明。内容上传保留可维护替代文本入口。图片里的关键卖点、规格和操作不能仅靠像素文字，提供可读 HTML 等价信息，不使用文件名或堆砌关键词作为替代描述。
- 普通文本对比度至少 4.5:1，大文本至少 3:1（18pt 或 14pt 粗体及相应等价值）；必要的控件边界、图形和状态信息按非文本对比度要求至少 3:1，标准例外须有依据。检查实际背景、图片叠字、禁用/悬停/焦点等状态，不只检查色板。
- 文字放大 200% 后信息与操作不丢失；验证相当于 320 CSS px 宽度的重排，除确需二维布局的内容外不依赖双向滚动。用户自定义文字间距不能造成裁切或重叠；不禁止缩放，不以全局固定高度隐藏溢出。
- 不强制用户通过动画理解信息。支持减少动态效果；自动轮播/持续运动按要求可暂停，避免闪烁。必要音视频提供字幕、文字替代和适当音频描述，不能只给播放按钮。

## 键盘、交互与交易

- 用 Tab/Shift+Tab、Enter/Space、组件适用方向键和 Escape 完成操作。焦点始终可见、不被 sticky header、弹窗或抽屉遮住；无键盘陷阱，不用正 tabindex 改乱顺序。
- 菜单、折叠、Tab、轮播、筛选、modal/cart drawer 有正确展开/选中状态；打开对话框合理移动焦点，关闭后返回触发点，按实际模态控制背景与焦点。不隐藏仍可聚焦的元素，不对可交互祖先误加 aria-hidden。
- 色板、图片选项、尺寸滑块和数量控制有文本名称与键盘方式；拖拽操作提供无需拖动的替代。点击目标按 WCAG 2.2 AA 的 24×24 CSS px 或合规间距/其他例外核查，触屏尽量更宽裕。
- 表单使用真实 label，说明必填、格式和单位；错误与字段关联，指出问题并给可执行修正方法，不只改红色。保留合法输入；成功、失败、加载和购物车/报价变化用适当 status/live region 通知，避免每次击键重复朗读大量信息。
- YMQ 与自定义计价使用同一合法状态。选项失效时清理价格并向用户说明，不能只隐藏；报价、加购成功/失败、缺货都能被辅助技术感知，不能用改文案掩盖错误金额。
- 核对登录支持粘贴、自动填充和可用认证方式；验证码不只依赖视觉。支付前能够检查并修正订单，错误恢复不清空所有资料。
- Shopify 托管结账、账户和第三方支付/App 按实际可控能力检查。主题无权限修复的环节记录供应商责任、可用替代协助渠道及未验证范围，不声称已修改第三方页面或绕过平台限制。

## 验收证据

已有 Lighthouse 用于自动初筛，记录版本、URL、视口、日期和问题；静态检查优先 API/CLI。键盘、实际朗读、动态焦点和缩放必须做相应运行验证。至少核对桌面与移动端；关键路径优先用可获得的屏幕阅读器组合实测，例如 NVDA/Chrome 或 VoiceOver/Safari，记录真实使用的组合，不伪造辅助技术测试结果。工具不可用时保留待测项，而不是写“通过”。不因为本规则自动安装未选的 Playwright 集成。

政策页本身也需验收：链接可发现、标题可导航、联系入口可操作、表单成功/错误可感知。交付列出已测页面/状态、未测项、阻断项与政策页预览链接；自动测试满分不是 WCAG 合规证明。

## 声明页发布

新站将无障碍声明加入既有 Page 与页脚菜单体系，不另造页脚。按站点语言填写模板，所有占位符必须替换；缺联系方式或实施证据时保留草稿并报告具体缺口，禁止用假邮箱或虚构服务时限发布。只列实际完成措施，计划项使用未来/持续改进措辞。已有已验证一致性报告时才据此写符合程度、覆盖范围和日期，不默认写“100% 无障碍”“已认证”或“满足所有法律”。

措辞欢迎不同能力的用户，说明他们怎样获得帮助；不要求用户披露诊断或残障证明。请求仅包含排查所需的页面、操作和可选设备信息，反馈渠道与隐私处理沿用站点实际流程。
